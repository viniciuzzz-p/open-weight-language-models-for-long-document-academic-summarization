# ENIAC 2026 Submission: Open-Weight Language Models for Long-Document Academic Summarization

**Note:** This repository is currently anonymized to comply with the double-blind review process for the National Meeting on Artificial and Computational Intelligence (ENIAC) 2026. All identifying information, author names, and affiliations have been removed.

## Overview

This repository contains the dataset, analysis scripts, and replication materials for our submitted paper. This work evaluates 19 open-weight language models on the automatic generation of abstracts from full academic theses. The models were executed locally with extended context windows, utilizing an iterative prompting strategy designed to maximize information density. The evaluation employed a custom Abstract Quality (AQ) metric based on the LLM-as-a-Judge paradigm. 

The results indicate better performance in larger-scale models, highlighting the *gpt-oss-120b*, while also evidencing the high competitiveness of intermediate architectures such as *qwen3-30b-a3b*.

## Dataset Description

The evaluation benchmark was constructed from a sample of 30 PhD theses extracted from a public repository of academic research. 

To ensure domain diversity, the sampling covered four major academic divisions:
* Mathematical, Physical and Life Sciences (MPLS)
* Medical Sciences (MSD)
* Social Sciences (SSD)
* Humanities (HUMS)

### Pre-processing and Noise Robustness
The original abstracts were formally isolated from the body text provided as input to the models and were reserved exclusively to act as the ground truth in the automated evaluation stage. Footnotes and figure captions were deliberately preserved in the input text to act as a noise robustness challenge. The dataset acts as a stress-test for context windows, with text loads reaching peaks of up to 126,018 tokens.

## Prompting and Evaluation Protocol

* **Generation Phase:** The abstract generation utilized a standardized English prompt structured to iteratively increase semantic density. The models were instructed to generate summaries across 5 iterations via Zero-Shot, maintaining a constant textual extension between 600 and 800 words. 
* **Validation Phase:** The generated abstracts were evaluated via the LLM-as-a-Judge methodology using an automated framework. We defined a custom generative metric named Abstract Quality (AQ).
* **Evaluation Dimensions:** The judge evaluated five strict dimensions: preservation of central scientific elements, semantic faithfulness, critical omissions detection, stylistic adequacy, and conciseness.

## System Requirements and Local Inference Infrastructure

All inferences were executed locally (on-premise) to investigate technical feasibility and extended context window sustainability. The experimental setup relied on the following hardware and software stack:

### Data Analysis and Pre-processing
* **Environment:** Python 3.x
* **Key Libraries:** `pandas` for dataset manipulation, and `matplotlib`/`seaborn` for generating the standardized academic figures.
* **Notebooks:** Jupyter environment utilized for exploratory data analysis, descriptive statistics, and tokenization metrics calculation.

### Software and Backend
* **Inference Engine:** Inferences were executed using a local server environment utilizing a C++ backend.
* **Model Format:** All 19 evaluated models operated entirely in the GGUF file format.
* **Execution Parameters:** The models were standardized to a 128k-token context window. The generation limit was set to 8,192 tokens with a temperature of 0.3.
* **Quantization Schemes:** To enable the execution of high-scale models on local hardware, 4-bit compression schemes were employed. The Gemma, Llama, Qwen, Phi, and Mistral families utilized traditional *Q4_K_M* quantization, while the *gpt-oss-120b* model employed the *MXFP4* (Microscaling Formats 4-bit) standard.

### Hardware Specifications
The hardware infrastructure consisted of a workstation equipped with three distinct high-capacity GPUs to handle the VRAM requirements:
* 1x NVIDIA RTX PRO 6000 Blackwell (96 GB VRAM)
* 2x NVIDIA RTX 5090 (64 GB total VRAM)
* 1x NVIDIA RTX A6000 (48 GB VRAM)

All models were loaded entirely into the video memory (VRAM) to maximize throughput and guarantee response time consistency.
